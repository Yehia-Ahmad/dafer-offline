## Context
In 7A the owner types ad spend by hand. In 7B the shop connects its own Meta ad account to Nota with a token it creates itself (a system user token of the shop's own Meta app). Nota then reads, every day, each Facebook/Instagram campaign's spend, impressions, reach and clicks, and shows them next to Nota's orders, sales and profit. **Read-only: Nota creates, changes or pays nothing on Meta in this stage** (that is 7C). The shop owns the app and the ad account, so Meta's limited ("standard") access with `ads_read` is enough; no app review and no business verification are needed.

## Decisions (already made; implement exactly)

### 1. Connection
- New permission `marketing.connect` («ربط حساب الإعلانات»), **owner only** in the role templates. The connection screen is in the website settings «التسويق» tab, visible with this permission.
- Fields: ad account id (`act_<digits>` or digits; normalized), system user access token, optional app secret (for `appsecret_proof` when the app requires it).
- "اختبار الربط" calls Meta and shows: account name, currency, time zone, account status, and the token's permissions (via the debug/permissions endpoint). Saving is allowed only after a successful test. "فصل الحساب" removes the token and stops syncing (synced data stays).
- **Secrets at rest:** the token and app secret are encrypted with AES-256-GCM using a new server secret `NOTA_SECRETS_KEY` (32 random bytes, generated by setup-server.sh and update.sh when missing, same pattern as the VAPID keys; dev/test get it from .env / the test runner). They are never returned to the browser (only "…last 4 chars"), never logged, never in audit details, never in error messages.
- Graph API version is a config value, default `v26.0` (the current one), overridable by env `NOTA_META_GRAPH_VERSION`. Base URL `https://graph.facebook.com`.

### 2. What is synced
- Meta campaigns of the ad account: id, name, status/effective status, objective, created time.
- Daily insights per Meta campaign: `spend`, `impressions`, `reach`, `clicks`, `inline_link_clicks`, with `date_start` as the day (it is in the ad account's time zone), `level=campaign`, `time_increment=1`.
- Stored as `MetaCampaign` and `MetaInsightDay` (unique per Meta campaign + day; upsert). Money parsed from Meta's decimal strings without float drift (store as integer minor units or use the project's money rounding consistently; say which in STEP 0).
- **Sync schedule:** on connect, backfill the last 90 days; then daily at 06:15 Cairo re-sync the last 7 days (Meta updates recent numbers). Plus a "مزامنة دلوقتي" button (rate-limited: once per 5 minutes). Implement the daily run as a systemd timer + a CLI script (`nota-meta-sync`, like the backup timer), installed by setup-server.sh/update.sh; a Mongo lock prevents two syncs at once.
- Errors: handle token invalid/expired, missing permission, account disabled, and rate limiting (back off and retry later, honour Meta's usage headers). Store `lastSyncAt`, `lastError` (a safe message) and show a banner on the marketing pages when the last sync failed.
- **Batch and page** requests (paging cursors, the batch endpoint or `level=campaign` on the account) so a sync stays well inside the limited tier's rate limits.

### 3. Linking Meta campaigns to Nota campaigns
- On a Nota campaign page (platform facebook or instagram): "اربط بحملة فيسبوك" lists the synced Meta campaigns (search by name, status); a Nota campaign can link to one or more Meta campaigns; a Meta campaign links to at most one Nota campaign.
- **Suggestion only:** if a Meta campaign's name contains the Nota campaign's code, show it first as «مقترح». No automatic linking.
- Unlinked Meta campaigns appear in a «حملات فيسبوك مش مربوطة» list with their spend, so nothing is hidden.

### 4. Currency
- If the ad account currency is EGP, use it as is.
- If not (often USD): a «سعر الصرف» setting with history (rate + effective date, entered by the owner). Each day's spend is converted with the rate effective that day. Results show the converted EGP amount and the original amount. If no rate covers a day, that spend shows in the original currency only, ROI/cost-per-order show «محتاج سعر صرف», and a banner explains it.
- If the ad account time zone is not Africa/Cairo, show a note that Meta's days are in <tz>.

### 5. Results (extends 7A, still read-only)
- For a Nota campaign linked to Meta: **«صرف فيسبوك»** (from insights, converted) is the spend used for cost per order, return on spend and profit after ads. Expenses linked to the campaign (7A) are shown separately as **«المدفوع المسجّل»** and are **not added** to the Meta spend (no double counting). For unlinked campaigns, 7A's rule stays (spend = linked expenses).
- New numbers for linked campaigns: impressions, reach, link clicks, CTR, CPC, CPM, and Meta link clicks next to Nota's own clicks and visits.
- Platform and total rows add Meta spend once.
- The daily chart can show Meta spend per day.
- **Accounting is unchanged:** Meta's spend is not posted. The help explains that the real charges Meta takes from the card are recorded as expenses when they happen (7A spend dialog, from the box that paid, e.g. a bank box for the card), and that the campaign page compares both.

### 6. Help (Arabic, step by step) — the shop setup guide
A new help section «ربط حساب إعلانات فيسبوك» with exact steps (from Meta's current UI and docs): Business portfolio, the ad account and its payment method, creating the shop's own Meta app (Business type), adding the Marketing API, creating an admin system user, assigning it the ad account, generating a token for the app with `ads_read`, finding the ad account id, pasting both in Nota, testing, and what each error means. Note that 7C will need `ads_management` (a new token then). Update the marketing results sections for the new numbers and the no-double-counting rule.

## Hard rules
- No change to how anything is priced or posted; results stay read-only aggregations.
- **No call to Meta writes anything.** Only GET requests (and the batch endpoint with GETs inside).
- No customer data is sent to Meta.
- Secrets never leave the server in any response, log or audit entry; a test checks every marketing/settings response and the logs for the token.
- Local business day rules from Fixes 1 for Nota's side; Meta's days are taken as Meta gives them.
