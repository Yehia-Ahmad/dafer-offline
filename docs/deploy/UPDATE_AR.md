# تحديث النظام على السيرفر

## 1) عمل إصدار على جهازك (Windows)
1. تأكد أن كل شيء committed (السكربت يرفض الشجرة غير النظيفة؛ للتجربة فقط: `--allow-dirty`).
2. من جذر المشروع:
   ```
   PS> node deploy/make-release.js
   ```
   يبني الواجهة (production) وينسخ الباك إند بدون `node_modules` ولا اختبارات ولا `.env`، ويكتب `release.json` (النسخة، الكوميت، التاريخ)، وينتج الملف:
   `release\release-<النسخة>-<الكوميت>.tar.gz` (المجلد `release/` خارج git).

- رقم النسخة (`1.0.0`) يؤخذ من `nota-backend/package.json`، واسم الملف يحتوي أيضاً رقم الـ commit. رفع نفس الـ commit مرتين يعطي نفس الاسم، و`update.sh` يرفض إصداراً هو الحالي أصلاً. لتغيير رقم النسخة عدّل `version` في `package.json` (الباك إند والفرونت) قبل عمل الإصدار.
- مكتبة `xlsx` موجودة داخل الإصدار (`backend/vendor`)، فالسيرفر لا يحتاج الاتصال بـ cdn.sheetjs.com.

## 2) الرفع
```
PS> scp release\release-<النسخة>-<الكوميت>.tar.gz root@<IP>:/root/
```

## 3) التحديث على السيرفر
```
PS> ssh root@<IP>
# /opt/nota/bin/update.sh /root/release-<النسخة>-<الكوميت>.tar.gz
```
ماذا يفعل بالترتيب:
1. نسخة احتياطية باسم `before-update-<النسخة>` في `/var/backups/nota`.
2. فك الإصدار في `/opt/nota/releases/<النسخة>-<الكوميت>` وتنفيذ `npm ci --omit=dev` (السيرفر يحتاج اتصالاً بالإنترنت).
3. تحويل `/opt/nota/current` للإصدار الجديد وإعادة تشغيل الخدمة (الـ migrations تعمل عند التشغيل كالمعتاد).
4. انتظار `/health` حتى 60 ثانية.
5. إذا فشل، بهذا الترتيب: (أ) إيقاف الخدمة أولاً (حتى لا تعمل النسخة القديمة على بيانات غيّرتها الـ migrations الجديدة)، (ب) إرجاع الرابط للإصدار القديم، (ج) استعادة النسخة الاحتياطية، (د) تشغيل الخدمة وانتظار `/health`، ثم يطبع الفشل بوضوح.
- عند الإيقاف أو إعادة التشغيل يستقبل التطبيق SIGTERM فيُنهي الطلبات الجارية (حتى 10 ثوانٍ) قبل أن يقفل، فلا يضيع طلب كاشير يحفظ فاتورة.
6. يُبقي آخر 3 إصدارات ويحذف الأقدم.

## 4) لو حصل Rollback
- الرسالة تقول `UPDATE FAILED and was rolled back`: المحل يعمل بالنسخة القديمة ببياناتها قبل التحديث.
- **تنبيه:** أي بيانات أُدخلت بين لحظة النسخة الاحتياطية والـ rollback (ثوانٍ إلى دقيقة) تُفقد. لذلك حدّث في وقت هادئ.
- شاهد السبب: `# journalctl -u nota-backend -n 100 --no-pager` ثم أصلح وأعد الإصدار.
- لو قالت الرسالة إن الـ rollback نفسه فشل: لا تُعد المحاولة؛ استعد يدوياً من النسخة المذكورة في الرسالة بـ `/opt/nota/bin/restore.sh <الملف>` (انظر `BACKUP_RESTORE_AR.md`).
- لا تحذف الملف المرفوع من `/root` قبل التأكد أن كل شيء يعمل.

## 5) تأكد بعد التحديث
```
# curl -s http://127.0.0.1:5000/health
# readlink /opt/nota/current
```
